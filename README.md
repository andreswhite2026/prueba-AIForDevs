# Colombian Language Academy — Local RAG Assistant

A locally hosted customer-service assistant for a language academy. The project combines a Vue 3 chat interface, a FastAPI backend, and Ollama models to answer academy questions from a curated knowledge base.

The application is designed to keep retrieval and generation local: documents are embedded with `nomic-embed-text`, relevant passages are retrieved with cosine similarity, and the final response is generated by a local language model such as `llama3`.

## Features

- **Local RAG pipeline** using Ollama, `nomic-embed-text`, and a local generation model.
- **Grounded answers**: the model is instructed to use only retrieved institutional context and to escalate when essential information is missing.
- **Multilingual responses**: the backend detects the query language and explicitly instructs the model to answer in that language. Semantic cache entries are separated by language.
- **Semantic cache** with cosine similarity and intent guards to avoid returning pricing answers for non-pricing questions.
- **Deterministic skills** for currency conversion and student enrollment.
- **Conversational enrollment flow**: users can provide their data in one or more messages; drafts are isolated by browser session and expire after 30 minutes.
- **Safe enrollment persistence**: validated JSON records include an ID, UTC timestamp, status, duplicate protection, and atomic writes.
- **Operational visibility** through `/health` and frontend metrics.
- **Development-friendly networking**: Vite proxies `/api/*` to FastAPI, avoiding browser CORS issues in local development.

## Requirements

- Python 3.10 or newer.
- Node.js 18 or newer.
- [Ollama](https://ollama.com/) installed and available locally.
- The following Ollama models:
  - `nomic-embed-text`
  - `llama3` (or another model configured through `MODEL_NAME`)

## Quick Start

Run each service in a separate terminal.

### 1. Install and start Ollama

```bash
ollama pull nomic-embed-text
ollama pull llama3
ollama serve
```

If `ollama serve` reports that the port is already in use, Ollama is already running.

### 2. Start the backend

```bash
cd backend
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
python -m uvicorn main:app --host 127.0.0.1 --port 8000 --reload
```

### 3. Start the frontend

```bash
cd frontend
npm install
npm run dev
```

Open the application at:

```text
http://127.0.0.1:3000
```

Using `127.0.0.1` consistently is recommended for this project because Vite and FastAPI are configured around the IPv4 local loopback address.

### 4. Verify the services

```bash
curl http://127.0.0.1:8000/health
curl http://127.0.0.1:3000/api/health
```

Expected response while the RAG index is ready:

```json
{
  "api": "ok",
  "ragReady": true,
  "ragError": null
}
```

The API remains available if Ollama is temporarily unavailable. In that state, `ragReady` is `false` and `ragError` provides a diagnostic message; initialization is retried in the background.

## Configuration

Create `backend/.env` only when defaults need to change. The file is ignored by Git.

```dotenv
OLLAMA_BASE_URL=http://127.0.0.1:11434
MODEL_NAME=llama3
EMBEDDING_MODEL=nomic-embed-text
ANALIZAR_DIR=analizar
CORS_ORIGINS=http://127.0.0.1:3000,http://localhost:3000
```

Relative backend paths are resolved from the `backend` directory, so the service behaves consistently whether it is launched from a terminal or an IDE.

## API Reference

### `GET /health`

Reports whether FastAPI is running and whether the RAG index is available.

```bash
curl http://127.0.0.1:8000/health
```

### `POST /chat`

Accepts a user prompt and an optional browser session identifier.

```json
{
  "prompt": "What schedules are available on Saturdays?",
  "session_id": "optional-client-session-id"
}
```

Example response:

```json
{
  "response": "...",
  "cached": false,
  "metrics": {
    "queriesProcessed": 1,
    "estimatedCost": 0.0002,
    "escalationRate": 0.0
  }
}
```

The frontend sends requests to `/api/chat`; Vite forwards them to FastAPI as `/chat`.

## RAG Workflow

1. Markdown and text documents are loaded from `backend/analizar/`.
2. Documents are split into overlapping word chunks.
3. Every chunk is embedded with `nomic-embed-text` through Ollama.
4. A new query is embedded and compared to document embeddings with cosine similarity.
5. The top matching chunks are inserted into a grounded prompt for the language model.
6. The model produces an answer only from that context or returns an escalation message.

The RAG index is built in the background at startup. A failed Ollama connection does not crash FastAPI.

## Language Handling

The backend uses `langdetect` to identify the incoming language. The detected language is passed explicitly to the model with a mandatory response-language instruction. This prevents Spanish source documents from forcing Spanish output for an English, French, German, Italian, or Portuguese question.

Cache entries retain their source language. A semantically similar English question cannot receive a previously cached Spanish response.

## Enrollment Workflow

Enrollment is a deterministic skill; personal data is not sent to the RAG model.

The assistant validates:

- Full name.
- Email address.
- Supported course: English, French, or German.
- Supported level: A1, A2, B1, B2, or C1.

Users can provide all fields in one message:

```text
I want to enroll; my name is Ana Pérez, my email is ana@correo.com,
and I want French level A1.
```

Or provide them in separate messages. The frontend sends a stable `session_id`, allowing the backend to retain only the unfinished draft for 30 minutes. `Cancelar inscripción` discards the draft.

Only complete, valid submissions are written to `backend/student_registrations.json`. Each final record includes a UUID, UTC creation timestamp, and `pending_confirmation` status. The file is ignored by Git because it may contain personal data.

## Knowledge Base

Place supported `.md` or `.txt` files in:

```text
backend/analizar/
```

Restart the backend after editing source documents so the in-memory index is rebuilt. Keep factual information clear and explicit: the assistant is intentionally configured not to infer unstated policies, schedules, or programmes.

## Troubleshooting

### The browser cannot reach the backend

Check both services:

```bash
curl http://127.0.0.1:8000/health
curl http://127.0.0.1:3000/api/health
```

If the first command fails, FastAPI is not running. If only the second fails, restart Vite and verify `frontend/vite.config.ts`.

### `ragReady` is false

Make sure Ollama is running and the required models are present:

```bash
ollama list
ollama pull nomic-embed-text
ollama pull llama3
```

### The browser blocks a local request but `curl` works

The backend and RAG are working in that case. Test with another approved browser or ask the local network/security administrator to permit local loopback traffic on ports `3000`, `8000`, and `11434`.

### A registration appears to use old fixed values

Restart FastAPI. Responses mentioning `Estudiante Local` belong to an earlier version of the enrollment implementation and should no longer appear after reload.

## Testing Checklist

Use the following manual checks during a demonstration:

| Scenario | Example | Expected result |
| --- | --- | --- |
| Grounded RAG | `What schedules are available?` | Answer based on indexed documents. |
| Language | `What is the payment policy?` | Answer in English. |
| Cache | Repeat the same question | Second response can display the cache badge. |
| Missing information | Ask for an unstated policy | Escalation instead of an invented answer. |
| Enrollment, one message | Full name, email, course, level | Valid JSON record is created. |
| Enrollment, multi-step | Provide fields separately | Draft is completed across messages. |
| Duplicate enrollment | Repeat the same registration | Duplicate warning; no new record. |
| Cancellation | `Cancelar inscripción` | Pending draft is removed. |
